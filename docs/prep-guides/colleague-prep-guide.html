6 Patterns That Repeat Across Every Scenario

These showed up in nearly every question regardless of domain

Pattern 1

Context Isolation

Something is polluting another thing's context. The answer is structural — fork, subagent delegation, conditional loading. Never "add more instructions."

Pattern 2

Error Handling

"Something failed. Now what?" Structured context wins: failure type + what was attempted + partial results. Never generic messages or silent suppression.

Pattern 3

Tool Selection

Agent picks the wrong tool. Start with tool descriptions. Fix root cause before adding routers, classifiers, or pre-processors.

Pattern 4

Batch vs Sync

Someone waiting = sync. Overnight/deferred = batch. Iterative tool-calling can't use batch at all — it's fire-and-forget, no mid-request interceptions.

Pattern 5

Few-Shot Boundaries

Few-shot is right for consistent, predictable patterns. When gaps vary unpredictably across cases, the answer is self-critique or structural change. Don't default to few-shot.

Pattern 6

Config Scope

Project scope (.claude/) = shared via git, team gets it. User scope (~/.claude/) = personal, not shared. Same-name skills: project takes precedence.

Anti-Patterns to Internalize

At least a third of questions test whether you can spot these. The fix column is the correct answer pattern.

1 Parsing natural language for when the agent is done  → check stop_reason
2 Using iteration caps as the primary stop mechanism  → safety fallback only
3 Putting critical business rules in prompts  → programmatic hooks / frontmatter
4 Using self-reported confidence for decisions  → never reliable, don't use
5 Escalating based on customer sentiment  → sentiment ≠ complexity
6 Returning generic error messages  → structured context (type + attempted + partials)
7 Silently suppressing errors, returning empty as success  → propagate errors with context
8 Giving agents too many tools  → cap at 4-5, least privilege
9 Same session reviewing its own code  → separate instance (confirmation bias)
10 Aggregate accuracy masking per-category failures  → per-category breakdown

#1 Trap: "Add instructions to the prompt" as an answer option. When you see it, verify: is there a deterministic fix instead?

Focus on understanding, not memorizing
