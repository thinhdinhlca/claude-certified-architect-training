Exam logistics

It is not a documentation recall test.

The CCA-F validates whether you can design production-grade applications with Claude. The four core technology areas are the Claude Agent SDK, the Claude API, Claude Code, and Model Context Protocol.

Reader fit

The target candidate has built with Claude, not just read about it.

Think of the exam as roughly 301-level. It assumes you can reason about real systems that use agents, tools, prompts, context windows, and operational guardrails.

  • Agentic applications with subagents, tools, orchestration, lifecycle hooks, and delegation.
  • Claude Code configuration through CLAUDE.md, Agent Skills, MCP integrations, and plan mode.
  • MCP tool and resource interfaces for backend integration.
  • Structured output using JSON schemas, few-shot examples, extraction patterns, and validation retry loops.
  • Context management across long documents, conversations, and multi-agent handoffs.
  • CI/CD usage for code review, test generation, PR feedback, and machine-readable output.
  • Reliability choices: error handling, escalation, human review, self-evaluation, and guardrail placement.
Glide expert angle A Glide builder will recognize many patterns: choosing the right data contract, deciding where business logic is enforced, routing edge cases to humans, and keeping automations reliable when inputs are messy.

Scenario pool

Six scenarios exist; four appear in your session.

Every question is anchored to one of the selected scenarios. Do not study the domains as isolated trivia. Study how each domain shows up in a system.

Scenario 1

Customer Support Resolution Agent

Tests: tool ordering, refund guardrails, escalation calibration, multi-concern request handling, and when prompt instructions are not enough.

Scenario 2

Code Generation with Claude Code

Tests: CLAUDE.md hierarchy, slash commands, path-specific rules, plan mode, and iterative refinement.

Scenario 3

Multi-Agent Research System

Tests: task decomposition, parallel subagents, explicit context passing, provenance, and structured error propagation.

Scenario 4

Developer Productivity

Tests: built-in tool choice, MCP server configuration, and distributing tools across agents without degrading selection quality.

Scenario 5

Claude Code for CI/CD

Tests: -p, --output-format json, --json-schema, fresh review instances, multi-pass reviews, and batch vs. sync decisions.

Scenario 6

Structured Data Extraction

Tests: nullable fields, tool_choice, validation retry loops, schema design, and batch processing strategy.

Scope control

Do not spend prep time on excluded topics.

The supplied exam notes exclude these areas. Treat them as distractions unless Anthropic updates the guide.

  • Fine-tuning
  • API authentication and billing
  • Specific programming language implementation details
  • Deploying or hosting MCP servers
  • Claude internal architecture
  • Constitutional AI or RLHF
  • Embedding models and vector databases
  • Computer use and browser automation
  • Vision or image analysis
  • Streaming API
  • Rate limiting
  • OAuth or API key rotation
  • Cloud provider configuration
  • Performance benchmarking
  • Prompt caching implementation
  • Token counting
